# PIX Keys

## `BrSpec::pixKey(PixKeyKind $kind = PixKeyKind::Any): PixKeySpecification`

A PIX key **as the DICT of the Banco Central stores it**, following section 1 of the DICT operational manual and the patterns of the DICT API specification. A key is compared with the DICT exactly as written, so nothing is trimmed and no punctuation is removed.

| `PixKeyKind` | Accepts |
| :--- | :--- |
| `Any` (default) | A key of any of the five kinds below. |
| `Cpf` | Eleven digits without punctuation, with the CPF check (a repetition is refused). |
| `Cnpj` | Fourteen characters without punctuation, numeric or **alphanumeric** (the DICT adopted the alphanumeric CNPJ from 2026-07-01), with the CNPJ check. Capital letters only, as in the DICT pattern. |
| `Phone` | A mobile number in E.164: `+55`, an area code of `PhoneSpecification::AREA_CODES`, `9` and eight digits, with nothing else. The DICT keeps mobile numbers only. |
| `Email` | An address in **small letters** of at most 77 characters (`PixKeySpecification::EMAIL_MAX_LENGTH`), as the DICT requires. |
| `Random` | The random key (EVP): a **UUID of RFC 4122 in small letters**, `xxxxxxxx-xxxx-Mxxx-Nxxx-xxxxxxxxxxxx` with the version `M` from `1` to `5` and the variant `N` one of `8`, `9`, `a`, `b`. |

- **The e-mail check is conservative**, a subset of the DICT pattern: the local part takes small letters, digits and ``!#$'*+/=?^_`{|}~-``, with dots only between them, and at most 64 characters; the domain has at least two labels of small letters, digits and inner hyphens, each of at most 63 characters. Quoted local parts, IP literals and characters outside that set are refused.
- **Case.** The DICT writes an e-mail and a random key in small letters, and its patterns have no capital letter: both are refused in capitals. Lower the case before checking when a form may receive capitals.
- **The random key** is generated by the DICT as a UUID of RFC 4122. The version is not narrowed to 4: the example of the DICT API specification (2.13.0), `123e4567-e89b-12d3-a456-426655440000`, is a version 1 UUID, and it is accepted. The nil UUID, a version outside 1 to 5, another variant and capital letters are refused.

<!-- tested: pix-keys -->
```php
<?php

declare(strict_types=1);

use Antevemus\ASpecificationBr\BrSpec;
use Antevemus\ASpecificationBr\PixKeyKind;

BrSpec::pixKey()->isSatisfiedBy('52998224725'); // true (a CPF)
BrSpec::pixKey()->isSatisfiedBy('529.982.247-25'); // false (a key has no mask)
BrSpec::pixKey()->isSatisfiedBy('12ABC34501DE35'); // true (an alphanumeric CNPJ)
BrSpec::pixKey()->isSatisfiedBy('+5511987654321'); // true (a mobile number)
BrSpec::pixKey()->isSatisfiedBy('+552134567890'); // false (a landline)
BrSpec::pixKey()->isSatisfiedBy('pix@bcb.gov.br'); // true
BrSpec::pixKey()->isSatisfiedBy('Pix@bcb.gov.br'); // false (capital letters)
BrSpec::pixKey()->isSatisfiedBy('123e4567-e89b-12d3-a456-426655440000'); // true (a random key: the example of the DICT API)
BrSpec::pixKey(PixKeyKind::Email)->isSatisfiedBy('52998224725'); // false (a CPF, not an e-mail)
```

The e-mail and the random key are the examples of the DICT API specification; the other values are fictitious or the public examples of the CPF and CNPJ pages.
